# Phase 4预注册计划（公开版）

## 目标

Phase 4不继续堆叠低价值冻结组合。核心问题是提高上游多图证据完整性、缩小自动Pipeline与标准证据条件的差距，并将解释性从病例级标量升级为可复算的token—视觉token原始矩阵。

如果最终产品被定义为“专业人员标准证据→AI诊断”，则自动上游实验可取消，Oracle路线转为主任务；此时视觉Grad/Attn不适用，不能声称图像空间解释。

## 最小实验矩阵

| ID | 任务 | 唯一变量 | 主问题 |
|---|---|---|---|
| R16 | 同病例多图→带image_id的结构化逐图证据 | 用病例上下文替代独立单图描述 | 是否减少证据遗漏并避免单图Full SFT的通用遗忘？ |
| E16-P | R16证据→既有鲁棒诊断器 | 只替换上游证据，不训练 | 单独改善上游是否提高真实诊断？该项不是训练Run。 |
| R17 | Oracle/R16生成证据1:1鲁棒诊断 | 下游训练证据与新上游匹配 | 是否进一步缩小Pipeline差距？ |
| R18 | 多图→结构化证据+最终诊断联合生成 | 联合监督替代两阶段级联 | 是否减少误差传播并保留显式证据？ |

R13渐进冻结不进入默认队列；固定冻结R10已经回答视觉塔是否必须更新的核心问题，动态调度会引入冻结时间与层数等额外混杂。

## 执行门禁

1. 先锁定同一批24个代表病例并验收原始解释性归档工具。
2. 所有正式Run按Phase1/2相同口径输出完整13项指标和病例级结果。
3. 任务目标不同必须声明target span组，不得混合比较解释性强弱。
4. 只对最终前两名策略做多seed复核；校准使用独立验证集，测试集只做锁定后的最终评测。
5. 原始临床矩阵、图像、病例manifest与热图只保存在受控环境，不进入公共仓库。

完整原始矩阵协议见[解释性归档规范](INTERPRETABILITY_ARCHIVE.md)。
