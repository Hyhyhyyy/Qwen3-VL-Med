# 实验矩阵与命名说明

这些运行代号用于区分方法，不公开私有队列的原始结果。

| 运行 | 训练/推理方法 | 任务含义 | 可公开结论边界 |
|---|---|---|---|
| R01 | 全量微调 | 原始病例级多图到单份病例报告 | 原始全量基线 |
| R02 | 全量微调 | clean_v2：清洗后的第二版病例级多图数据 | 数据质量改善值得后续沿用 |
| R03 | 全量微调 | 单图到单图描述，并测试不同病例聚合路线 | 任务粒度和级联遗漏会影响结果 |
| R03-01 | 聚合分支 | 根据单图输出生成短诊断 | 与直接病例报告任务不可直接等价比较 |
| R03-02 | 聚合分支 | 先抽取预测证据，再生成诊断 | 中间证据遗漏可能级联 |
| R04 | LoRA消融基线 | 视觉LoRA + 投影器直接更新 + 语言LoRA | 用于受控冻结比较 |
| R05 | LoRA消融 | 冻结视觉侧，保留语言适配 | 视觉适配存在贡献但不是最大因素 |
| R06 | LoRA消融 | 冻结投影器，保留视觉与语言LoRA | 未观察到稳定的投影器重训收益证据 |
| R07 | LoRA消融 | 冻结语言主干，保留视觉适配 | 语言适配不可缺 |

## Full、LoRA和冻结的准确含义

- **严格全量微调（Full）**：目标模块原始参数参与梯度更新。
- **LoRA适配**：目标层原始大权重冻结，新增低秩矩阵参与训练；模块仍然在学习。
- **完全冻结**：原始参数不更新，且没有该模块的LoRA或其他可训练适配参数。
- **modules_to_save**：指定模块原始参数会直接更新并保存，不应误写为LoRA。
- 学习率很低不等于冻结；目录名也不能证明真实参数状态。

每次实验必须以训练配置、可训练参数统计、adapter张量和保存产物联合确认真实更新状态。
