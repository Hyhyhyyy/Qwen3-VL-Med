# 公开成果与工程经验

## 公开范围

本文只记录不会暴露临床样本、内部系统或模型资产的工程事实和方向性结论。绝对病例级结果、预测文本、数据规模细节及可关联内部运行的信息不在公开范围内。

## 已完成的工程闭环

本实践形成了完整的视觉语言模型研究流水线：

1. 数据审计、清洗、任务转换和按病例隔离的数据划分；
2. 全量微调、LoRA及模块冻结配置生成和静态核验；
3. 多GPU训练、smoke test、checkpoint保存与重载；
4. 固定解码条件下的批量推理和逐样本指标记录；
5. 聚合指标、病例配对比较、bootstrap置信区间和错误分层；
6. 配置、日志、模型产物、评测版本、报告和SHA-256清单归档；
7. 公开发布前的白名单复制、隐私扫描、语法检查和单元测试。

## 可以公开的主要结论

### 1. 数据清洗不是附属步骤

统一格式、删除无效模板残留并提高诊断目标的一致性后，多项诊断概念和临床事实代理呈改善趋势。它说明数据目标是否清晰会直接影响模型学习，而不只是影响文字是否规范。

### 2. 任务粒度会改变模型能力

病例级多图直接生成完整报告、单图生成局部描述、局部证据再聚合诊断是不同任务。不同任务的损失和文本指标不能直接横向排名，也不能用目录名称替代对真实输入输出的核查。

### 3. 中间证据级联存在遗漏传播

当病例诊断依赖先生成的局部证据时，上游漏掉的关键发现很难由下游恢复。更适合产品目标的监督结构应同时保存逐图所见、证据图ID和病例级综合诊断，而不是只保留其中一端。

### 4. 语言适配是当前消融中最关键的部分

冻结语言主干时，诊断、事实覆盖、遗漏和幻觉代理出现一致恶化。视觉适配也有可检测贡献，但幅度相对较小；投影器是否需要重训没有得到稳定证据。该结论只适用于完成的LoRA消融，不能未经验证外推到所有全量微调设置。

### 5. 全量微调与LoRA没有绝对胜负

现有同病例比较支持LoRA可以接近全量微调，但不足以声明等价、非劣或更优。后续必须在相同数据、任务、病例、解码和临床终点下比较。选择全量微调探索性能上限是一种实验策略，不是“Full天然更准确”的结论。

### 6. 自动指标只能做研发筛选

文本相似度和参考报告规则代理能发现回归与错误模式，但不能证明图像证据真实存在，更不能替代病理医师对重大误诊、关键漏诊和报告可接受性的判断。

### 7. 多图分层监督已进入联合结构化验证

目标输入为同一病例多张图；输出包含逐图质量、所见、阳性/阴性证据、不确定性，以及病例级综合诊断、鉴别、分级分期、证据图ID和资料缺口。R16/R18已验证这一结构的训练与解析可行性，但尚未完成临床专家证据核验、外部验证与校准，因此不能描述为已经可部署。

### 8. 第三阶段复现了冻结投影器的 Pareto 趋势

在更严格清洗数据的同任务对照中，投影器冻结的视觉与语言 LoRA 路线与 Full SFT 保持接近的医疗文本生成和严格诊断趋势，同时在统一公开通用基准上表现出更小的能力遗忘。该结果与首轮消融方向一致，但严格诊断和校准仍未解决，因此只能作为研究候选，不能写成临床优越性或部署结论。

### 9. 病例级归因不等于空间解释

既有 Run 保存的梯度和注意力是固定病例样本上的视觉 token 份额及逐图贡献，可用于跨 Run 分布与相关性分析，但不足以重建目标 token 到图像 patch 的空间热图。下一阶段必须保留 token 级 attention、gradient、Gradient × Attention、各 attention head 以及 patch 坐标映射。详见 [统一 13 项评测机制](STANDARD_EVALUATION.md)。

### 10. 固定冻结视觉塔形成了更强的完整报告对照

在相同严格清洗任务上，冻结视觉塔并训练投影器与语言模型的R10保持了接近Full SFT的医疗生成和诊断趋势，同时明显降低公开通用benchmark的alignment tax。这说明视觉塔权重漂移是全量更新遗忘的重要来源之一；冻结权重不等于模型不使用视觉特征。

### 11. 证据鲁棒训练可以改善真实级联

R15使用Oracle与上游生成证据的配对混合监督，在保持总样本暴露量可比的条件下，真实Pipeline严格诊断相对原R09-02显著改善。Oracle端变化未达到配对显著性。该结果支持训练—推理证据分布匹配，但没有消除上游证据质量瓶颈。

### 12. 最高Oracle分数不等于自动系统效果

Oracle回答“标准证据已经可用时，下游诊断器能做到什么”；Pipeline回答“自动上游生成证据时，整个系统能做到什么”。若真实工作流由专业人员输入标准证据，可以将Oracle定义为人机协同主条件；否则必须报告Pipeline。详细规则见[Oracle与Pipeline报告协议](ORACLE_PIPELINE_PROTOCOL.md)。

### 13. 单模型联合结构化监督优于独立证据级联的研究优先级

R16让同一个模型一次读取病例多图并联合输出整体诊断、逐图分析和跨图证据，避免把模型生成描述再次作为另一个模型的唯一输入。它取得当前同数据对照中更高的严格诊断点估计与完整结构输出，因此比继续扩展独立Pipeline更值得优先研究。但其置信区间与对照重叠且校准明显恶化，结论只能是“候选”，不能写成临床优越。

### 14. 配置优势不能脱离数据与任务阶段外推

R17在严格清洗完整报告任务上恢复R06的LoRA秩、学习率和四卡有效batch策略，但没有重现首阶段的明显优势。R14与R17共同说明，参数更新策略必须在目标数据和输出任务上重新受控验证，不能仅凭早期Run排名选择最终模型。

### 15. 联合目标上的LoRA没有超过冻结视觉Full

R18只改变R16的参数更新方式，使用视觉/语言LoRA并冻结projector。其严格诊断和多项文本指标没有超过R16。当前结果不支持继续围绕相同LoRA组合堆叠实验；若目标只有诊断效果，应优先处理R16校准、错误分层、重复seed和外部验证。

## 失败与修复经验

- 注意力实现与模型版本不兼容时，优先通过最小smoke test确认根因，再切换到经过验证的SDPA实现，而不是直接扩大训练规模。
- 训练成功不等于成果可恢复；正式运行前必须单独验证周期checkpoint、最终保存、adapter结构和重载推理。
- 分布式策略、CPU offload和输入分辨率会显著影响耗时，跨执行栈的训练时间不能解释为算法优劣。
- 固定随机种子不等于位级确定性；未确认确定性算法时，应如实记录可复现级别。
- 评测应保留逐记录基础字段，否则聚合分数无法定位问题，也无法独立重算。
