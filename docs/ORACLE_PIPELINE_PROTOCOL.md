# Oracle与Pipeline报告协议

## 定义

- **Pipeline**：上游模型从实际可用输入生成证据，下游诊断器接收这些生成证据。这是自动级联系统的现实输入条件。
- **Oracle**：下游诊断器接收人工标准证据。它是理想输入上限，或在真实工作流中确有专业人员提供同等级证据时的人机协同条件。

## 强制报告规则

1. 自动图像到诊断系统的主表必须报告Pipeline；Oracle进入补充上限表。
2. 如果研究目标明确是“专业人员证据到AI诊断”，可将Oracle设为主条件，但任务名称必须相应修改，不能宣称自动图像诊断。
3. Pipeline与Oracle不得平均、择优合并或共享一个未经标注的指标单元格。
4. 同一下游模型在两种输入上的公开通用benchmark相同，不应重复解释为两个模型。
5. Oracle证据必须审计诊断字符串、同义词、缩写、分期和模板泄漏；泄漏审计前只能称为上限，不能称为无泄漏性能。
6. 比较Pipeline/Oracle时使用相同病例顺序和病例级配对统计。

## 推荐主表名称

- 自动流程：`Run-ID Pipeline`
- 人工证据流程：`Run-ID Human-evidence`或`Run-ID Oracle`
- 上限：`Run-ID Oracle upper bound`

任务选择优先于分数选择：输入证据是否在真实推理时可获得，决定哪个指标有意义。
